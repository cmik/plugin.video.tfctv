# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Kodi (19+, Python 3) video add-on, `plugin.video.tfctv` ("iWantTFC"), that scrapes/calls the iWantTFC website and API (`api.iwanttfc.com`, `www.iwanttfc.com`). It is unofficial. There is no build system or linter, and the only tests (`tests/`) cover the models, user data and catalog seed with a faked `control` module: the rest of the code only runs inside Kodi (it imports `xbmc`, `xbmcgui`, `xbmcaddon`, etc.), so it cannot be run standalone. Verify changes by reading Kodi's log (`~/Library/Logs/kodi.log` on macOS; enable the add-on's `debug` setting; `logger` in `resources/lib/libraries/logger.py` writes to it). Kodi runs its own installed copy in `~/Library/Application Support/Kodi/addons/plugin.video.tfctv/`, not this folder, so edits here have no effect until copied there (it is a plain copy, not a symlink).

`test_api.py` is a standalone scratch script (plain urllib + cookie file) for poking at the web API outside Kodi; it is gitignored along with `notes2`, `test_cookies.txt`, `API_MAP.md` and `REFACTORING_SUMMARY.md`. The `notes` file and `kodi.log` are untracked scratch files and may contain captured requests with credentials: never copy their contents anywhere.

Versions: between two releases `master` carries a development version `X.Y.0~devN` (Kodi compares versions like Debian: `~` sorts before the same version without it, so `3.5.0 < 3.6.0~dev1 < 3.6.0`: a development build never replaces a release and the release upgrades it). `changelog.txt` has one entry for `X.Y.0` that collects the changes of the cycle, and `<news>` starts with it. Raise N when a change needs the upgrade step (`upgradeDB` runs when the version changes) or to tell builds apart. Only the version without suffix is released: the release PR removes the suffix, writes the final `<news>`, and the tag `vX.Y.0` (a tag can not contain `~`, so a development version can not be tagged by mistake). A release: set `version` and `<news>` in `addon.xml`, `changelog.txt`, and regenerate `addon.xml.md5`.

## Architecture

Entry points (declared in `addon.xml`):
- `default.py`: plugin entry. Parses `sys.argv[2]` into params, then dispatches on an integer `mode` through one large `if/elif` chain. Mode constants live in `resources/config.py` (alongside base URLs, user agents, DB paths). Navigation modes call `resources/lib/indexers/navigator.py` (`navigator` class builds Kodi directory listings); action modes call `tfctv` functions directly. It also runs `resources/upgrade.py` (DB/settings migration) when `lastVersion` differs from the add-on version.
- `service.py`: background service started at Kodi startup: a local HTTP proxy (`ProxyHandler`, used for streaming with cookies/headers) and the library checker.

Source layer, `resources/lib/sources/`:
- `tfctv/` is a package: callers do `from resources.lib.sources import tfctv` and use `tfctv.someFunction()`. `tfctv/__init__.py` star-imports its submodules; when adding a function, make sure it is public (no leading underscore) in its submodule.
- `tfctv/` modules: `api.py` (HTTP via urllib with a shared cookie jar/opener, `callServiceApi`/`callJsonApi`; call `reset_opener()` after cookie changes), `auth.py` (email/password and Facebook login against the iwanttfc API; the login flow was recently reworked), `user.py` (profile, subscription, devices, fingerprint/geo), `catalog.py` (shows, episodes, my list, search, catalog refresh; it re-exports what moved out of it), `graphql.py` (the website GraphQL calls), `formatters.py` (assets to add-on structures), `rails.py` (website collections and rails), `db.py` (the `showDB`/`episodeDB`/`castDB` instances), `playback.py` (resolving media info and playing episodes/live streams), `library.py` (export to the Kodi library, NFO generation), `utils.py`.

Persistence: `resources/lib/models/` holds sqlite-backed models (`Model` base class; `shows`, `episodes`, `showcast`, `celebrities`, `library`, `userdata`) exposed as `showDB`, `episodeDB`, `libraryDB`, `castDB`. Caching goes through `resources/lib/libraries/cache.py` and `executioncache.py`. `resources/lib/libraries/control.py` wraps Kodi APIs (settings, dialogs, string lookup via `control.lang(id)`, paths); `trakt.py` is a new, uncommitted Trakt integration. Localized strings are in `resources/language/` and settings UI in `resources/settings.xml`.

User data is kept apart from the catalog: `userdata.db` (`models/userdata.py`: `MYLIST`, `STATS` = views/rating/votes of shows and episodes, `META`). `Show`/`Episode` add these fields to what they read (`_applyUserData`) and route `update()` of `mylist`/`views`/`rating`/`votes` to it; `set()` never writes them in the catalog databases. The catalog databases (shows, episodes, celebrities) are a cache that can be refreshed, reset or replaced. Previous versions stored My List and the counters in the catalog columns: `UserData.importLegacy()` moves them once (upgrade, and before a catalog reset).

View history: each playback adds a row to the `HISTORY` table of `userdata.db` (`sources/tfctv/history.py` `recordView`, called by `getMediaInfo`), with the title, show and thumbnail kept so it can be listed even when the catalog is replaced. The root menu entry *My View History* (`VIEWHISTORY` mode, setting `displayViewHistory`) lists the last viewed first; removing an entry or clearing the history also resets the viewed flag. Every episode read carries `dateviewed` (its last view, from `HISTORY`), which `formatVideoInfo` gives to Kodi as `lastplayed` so the *Last played* sort works in every list. Items are flagged by `playcount` (`formatVideoInfo` -> `InfoTagVideo.setPlaycount`, from the `STATS` view count), whatever listing they appear in. Episodes that only had a view count are listed once at upgrade (`libraries/viewhistory.py`). `history.db` (old model, ids of the old API) was not used anymore: the upgrade removes it.

Resume: the service (`service.py` `PlaybackMonitor`, a `xbmc.Player`) follows what the plugin plays: `playEpisode` puts the episode id in the property `tfctv.episodeid` of the played item (and in the window property `tfctv.nowplaying`, `libraries/playertracker.py` `encode`, as a fallback) just before `setResolvedUrl`, the monitor reads it in `onAVStarted` (`getPlayingItem()`; its `Playback tracking:` lines are in the Kodi log, the service has no debug setting), samples the position every 5 s and, when playback stops, stores it in the `PROGRESS` table of `userdata.db` (kept between 30 s and 90 % of the episode, forgotten beyond or when it ends). `Episode._applyUserData` adds `resumeposition`/`totaltime` to the episodes read, which `formatVideoInfo` turns into `InfoTagVideo.setResumePoint` on the list items: Kodi then shows its progress bar and handles resuming itself with its own *Resume from* / *Play from beginning* choices. The plugin must not set `StartOffset` on the resolved item (it overrides Kodi's *Play from beginning*, which plays the same URL as any other play). The root menu entry *Continue Watching* (`CONTINUEWATCHING`, setting `displayContinueWatching`) lists the resumable episodes. Directories declare their content type and sort methods through `navigator.endDirectory(content=..., sortMethods=...)` (`control.setListing`).

Scheduled catch-up: the service (main loop of `service.py`, every 10 minutes starting 2 minutes after it starts, setting `catalogCheckHours`, 0 = never) runs `catchUpCatalog` (`RunPlugin`, mode `CATCHUPCATALOG`, `caller=service`) when `libraries/catchup.py` `due` says so (time of the last look in the `catchUpAt` META of `userdata.db`; never while something is played). It loads the shows of the website collections that aren't known, repairs the stored details, loads again the episodes of the shows of My List (`getShow` returns the number of new episodes in `newEpisodes`) and, from the service, notifies them (setting `notifyNewEpisodes`).\n\nUp Next: when an episode starts, the service (`PlaybackMonitor._upNext`) tells the `service.upnext` add-on (optional dependency, setting `upNext`) which episode follows: `libraries/upnext.py` `buildData` takes the next episode of the show from `episodeDB` (the air date is not stored, so the order is the one of the titles: `S2 E10`, else the day in `Ep 24th Oct 2026 - ...`, else the episode number), and `send` hands the data over as a `JSONRPC.NotifyAll` from `<addon id>.SIGNAL` with the message `upnext_data` (base64 encoded JSON, with a `play_url` that plays the next episode). Nothing is sent for movies, for the last episode, or when Up Next is not enabled.

Seasons: a show listed from the database (categories, search, My List) offers the choice of the season (`SEASONS` mode) when its `NBSEASONS` column (stored by `formatAssetToShow` from the asset; 0 means unknown, older databases get the column by `ALTER TABLE`) is above 1; `navigator.showMode` decides (and `showTarget` builds the *Go to the show* context entry of Continue Watching and My View History), and the catch-up (`repairShowDetails`, also started by `upgradeDB` when some shows have `NBSEASONS = 0`) loads the details again of the shows that lack it.

Cast (`models/showcast.py`, table `SHOW_CAST` with a `SOURCE` column): `getShow` stores the cast the API gives (`replaceApiCast`, source `api`, rewritten at each refresh) and `getCast` returns it followed by the actors only the old catalog knew (source `legacy`). The legacy links are `resources/data/legacy_cast.json`, built by `.github/scripts/build_legacy_cast.py` from the old databases (matched to the current shows by title) and merged once at upgrade (`libraries/legacycast.py`, which also purges the rows stored before `SOURCE` existed).

Trakt show matching (`libraries/trakt.py`): Trakt finds shows by title, so `Trakt.candidates` searches the variants of the title (`titleVariants`: with and without the name of the star, without a subtitle) until one matches, `pickShow` returns the id only when one candidate is surely the show (the same title, the only variant, the only match, the right year), else the show is `unresolved`: the service notifies once and the context menu entry *Choose the show on Trakt* (`TRAKTLINK`, `chooseTraktShow`) lets the user pick among the 5 most likely (`suggestions`), search another title or say it is not on Trakt. The ids are kept in the META `traktShow:<show id>` (a digit = the id, `skip` = not on Trakt, `unsure:<time>` = look again after a day).

Online search: the search menu entry *Search the website (online)* (`enterSearch` type `online`, `searchOnline`) asks the website search (`searchCatalog`), whatever the databases know, and `formatSearchResults` formats what it finds: shows, movies and documentaries (`stored`) are added to the databases when missing (that is how a title a catalog reload does not bring is recovered; their episodes load when the show is opened), channels and live events play as `livestream` (not kept: the Home rail lists only a few), specials play as movies.

Top Picks: the main menu entry *Top Picks Near You!* (`TOPPICKS`, `getTopPicks`) is what the website search lists for an empty query (a rail of 50 for the user's country), shown in the website's order and stored like the online search (`keepFound`).

Live TV: the main menu entry *Live TV* (`LIVETV`, setting `displayLiveTV`, `getLiveTV` in `rails.py`) lists the channels then the live events found in the rails of every website collection (what the website offers in the user's country: 11 channels and about 9 events for FR, the same as the Home rails; no other query finds more). Nothing is stored: the events come and go and the list is one cached read.

Watchlist sync: My List (`MYLIST` of `userdata.db`) and the iWant watchlist (GraphQL `watchlist`, `POST /watchlist/watchlist` `{assetId}`, `DELETE /watchlist/watchlist/<id>`, Authorization bearer; `sources/tfctv/watchlist.py`, the decision of each way to settle in `libraries/watchlist.py`). Tools > *Synchronize My List with iWant* (`SYNCWATCHLIST`) asks, when the lists differ, to merge (nothing removed), replace Kodi's or replace iWant's (a confirmation says how many are removed); only shows, movies and documentaries are compared. Once a synchronization succeeded (META `watchlistSyncedAt`) and while the setting `syncWatchlist` is on, adding to or removing from My List in Kodi (`setMyList`) is sent to iWant (`pushChange`); changes made on the website come only with the next synchronization. `callServiceApi`/`callJsonApi` take a `method` (DELETE).

Catalog seed (`resources/lib/libraries/seed.py`): on a first installation or an update from a version < 3 (`seedReason`), `tools.importDBFiles()` downloads `catalog-seed.zip` + `manifest.json` from the GitHub release tagged `catalog-seed` (setting `catalogSeedURL`), checks sha256 and the databases, keeps the replaced ones as `.bak`, remaps My List by title if ids changed, then starts `catchUpCatalog` in the background (loads the shows that are new since the seed). Build and publish a seed from a profile whose catalog was loaded (Reload Catalog Cache with episodes):

    python3 .github/scripts/build_seed.py "$HOME/Library/Application Support/Kodi/userdata/addon_data/plugin.video.tfctv" /tmp/seed
    gh release create catalog-seed /tmp/seed/catalog-seed.zip /tmp/seed/manifest.json --title "Catalog seed" --notes "..."   # first time
    gh release upload catalog-seed /tmp/seed/catalog-seed.zip /tmp/seed/manifest.json --clobber                              # next ones

Tests (outside Kodi, run in CI): `python -m unittest discover -s tests`.

The branch `nw_adapt_v3` is adapting the add-on to the new iWantTFC website/API (v3.0.0 beta). `API_MAP.md` (local) documents the endpoints used by each `tfctv/` module.

## Playback / DRM notes

Playback uses Widevine through `inputstream.adaptive`: `retrieveMediaInfo()` calls `POST /entitlement/playback/start/{id}` and returns an MPD URL plus an EZDRM license URL (short-lived JWT in `CustomData`, about 2 minutes). EZDRM returns a raw binary license, so `response_data` in the `license_key` must stay empty (not `JBlicense`). The request body must mirror the website's, including `deviceId`, otherwise the license token carries `deviceId: unknown` and EZDRM answers `ACCESS_DENIED` ("License update not successful (no keys)" in the log).

Environment requirement found while debugging: Kodi 21+ with the current Widevine CDM (4.10.3112.0 at the time). Kodi 20.1 crashes with SIGILL in `libwidevinecdm.dylib` (`VerifyCdmHost_0`) on that CDM, and the older CDM 4.10.2934.0 gets `ACCESS_DENIED`. Crash reports are in `~/Library/Logs/DiagnosticReports/Kodi-*.ips`.
